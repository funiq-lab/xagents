# Internationalization (i18n)

**Key constraint:** SSG cannot access headers or cookies, so every locale must come from the URL params.

## Server Components (`plugins/i18n/index.ts`)
```tsx
export default async function Page({ params }: { params: Promise<{ lng: string }> }) {
  const { lng } = await params
  const { t } = await getTranslation(lng, ['namespace'])
  // ...
}

// Do NOT call headers() or cookies(); it breaks static generation.
```

## Client Components (`plugins/i18n/client.ts`)
```tsx
'use client'
import { useTranslation } from '@/plugins/i18n/client'

export default function Component() {
  const { t } = useTranslation(['namespace']) // language inferred from the route
}
```

## Configuration
- Supported locales: `zh_CN` (default) and `en`.
- Translation files live at `/locales/{lang}/{namespace}.json`; the default namespace is `global`.

## Routing Requirements
Place every page under `/app/[locale]/` and expose:
```tsx
export async function generateStaticParams() {
  return languages.map(lang => ({ lng: lang }))
}
```

## Common Pitfalls
- **“Route /[locale] … used headers”** – remove `headers()`/`cookies()` calls and rely on `params`.
- **“react-i18next:: You will need to pass in an i18next instance”** – client components must use `useTranslation`, server components must use `getTranslation`, and `plugins/i18n/i18next.ts` must export the configured instance.
